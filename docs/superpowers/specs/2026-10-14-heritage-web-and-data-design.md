# 历史建筑 Web 展示与业务数据设计

日期：2026-10-14  
状态：设计已确认

## 1 背景

平台第一部分需要提供面向用户的上海历史建筑浏览体验，第二部分需要形成可上传、编辑、审核和发布的权威业务数据。页面不能依赖大模型临时生成固定内容，也不能让前端直接访问 SQL、向量库或 Agile Agent。

本设计与《单建筑结构化图纸与历史档案 RAG 设计》配套：本设计定义 Web 展示、固定业务字段、权限、查询目录和管理工作流；结构化图纸、历史档案证据和 RAG 的内部实现沿用该文档。

## 2 目标

- 首页显示上海地图和历史建筑 slider。
- 点击地图或 slider 后在同一页面进入聚焦状态，不发生整页跳转。
- 聚焦状态固定展示路径、地图、当前节点完整信息和当前节点直接子节点。
- “处、自然幢、特色部位、构件”复用同一套递归页面结构。
- SQL 保存正式业务数据，字段和数据类型固定。
- 已发布页面从 SQL 和展示快照读取，RAG 只用于图纸、档案检索和证据组合。
- 所有编辑先进入变更集，经分项审核后按整栋建筑原子发布。
- 公众、项目管理人员和行业管理人员使用同一份发布快照，由服务端执行节点、字段、媒体和关系级权限过滤。

## 3 非目标

- 不允许前端提交任意 SQL 或任意向量检索条件。
- 不使用运行时大模型生成首页、铭牌、固定字段或正式历史说明。
- 不为每种节点类型分别开发一套页面。
- 不使用 EAV 或任意 JSON 代替正式业务字段。
- 不默认把全部图纸页、OCR 区域和内部档案暴露为公众导航节点。
- 不让 Agile Agent 代替 Web 服务、权威数据库、编辑后台或发布服务。

## 4 总体架构

```text
Web 前端
   │
   ▼
历史建筑 Web 服务
   ├── 首页、地图和 slider
   ├── 当前节点完整信息
   ├── 路径和直接子节点
   ├── 权限过滤
   ├── 固定查询目录
   └── 展示缓存
        │
        ├── SQL / 展示快照
        ├── 对象存储 / 媒体服务
        └── Agile Agent
             ├── 图纸结构化检索
             ├── 历史档案 RAG
             ├── 证据组合
             └── 建筑知识问答

管理后台
   ├── 固定字段编辑
   ├── 节点与关系编辑
   ├── 文件上传
   ├── OCR 与档案审核
   └── 整栋建筑发布
        │
        ├── SQL 权威数据
        ├── 异步处理服务
        ├── 对象存储
        └── 发布与索引服务
```

Web 服务是前端的唯一数据入口。即使 Agile Agent 暂时不可用，首页、地图、节点导航、固定字段、媒体和已发布历史信息仍然正常服务。

## 5 前端页面状态

### 5.1 首页状态

首页负责发现和进入：

- 上海地图显示“处”或建筑聚合点。
- 历史建筑 slider 显示主图、名称和短说明。
- 地图范围变化可以同步筛选 slider。
- 点击地图中的“处”进入该“处”的聚焦状态。
- 点击 slider 中的历史建筑直接进入该自然幢的聚焦状态。

### 5.2 聚焦状态布局

```text
┌────────┬──────────────────────────────────────┐
│ 80rpx  │              地图                    │
│ 路径栏 ├──────────────────────┬───────────────┤
│        │ 当前节点完整信息      │ 直接子节点列表 │
│        │ 主图 标题 铭牌 详情   │               │
└────────┴──────────────────────┴───────────────┘
```

- 左侧为宽度 `80rpx` 的垂直路径栏。
- 顶部地图保留并定位到当前建筑或节点。
- 下方圆角内容面板与地图形成连续聚焦状态。
- 中部左侧约占内容区 `40%`，展示当前节点主图、标题、铭牌和完整信息。
- 右侧严格显示当前节点的直接子节点列表。
- 中部信息区与右侧列表分别独立滚动。
- 主图可以短距离吸附，下面按身份、建造、历史人文和运维四类信息折叠展示。

### 5.3 递归导航

```text
处 → 自然幢 → 特色部位 → 构件
```

点击子节点不更换页面框架，只更新：

- 路径；
- 地图定位；
- 当前节点主图和完整信息；
- 当前节点直接子节点列表；
- 浏览器地址中的当前节点 ID。

路径祖先可点击。首页入口恢复地图与 slider。浏览器前进、后退和深链接必须有效。切换时保留旧内容，待新数据加载完成后再替换，避免空白闪烁。

## 6 当前节点统一读模型

所有可导航节点复用 `NodeView`：

```json
{
  "release": {
    "buildingReleaseId": "release-018",
    "schemaVersion": "v1"
  },
  "context": {
    "nodeId": "node-001",
    "nodeType": "NATURAL_BUILDING",
    "buildingId": "building-001",
    "permissionScope": "PUBLIC"
  },
  "path": [],
  "mapContext": {},
  "current": {
    "title": "",
    "subtitle": "",
    "status": "",
    "heroMedia": {},
    "plaque": {},
    "summary": "",
    "facts": [],
    "sections": []
  },
  "children": []
}
```

`sections` 使用固定类型的展示块承载四类正式信息。不同节点类型可以配置块的显示顺序，但不能改变正式字段的含义和类型。

### 6.1 展示快照

每次整栋建筑发布为每个节点生成只读 `NodeViewSnapshot`：

- 当前节点标题、简介、铭牌、主图和四类信息区固化到快照。
- 路径由发布版本中的父子关系计算。
- 地图定位默认继承所属建筑，节点可以提供受控覆盖。
- 子节点列表不复制进父快照，按当前发布版本的直接 `CHILD` 关系组装。
- 草稿、新增和移动不影响已发布快照。
- RAG 提取内容只有审核并进入发布版本后，才能成为正式展示内容。

缓存键：

```text
buildingReleaseId + nodeId + permissionScope + language
```

## 7 子节点列表

子节点卡片只返回：

- 节点 ID 和节点类型；
- 标题；
- 缩略图；
- 一至两行短说明；
- 状态或价值标签；
- 直接子节点数量；
- 展示排序；
- 是否存在全景或模型。

列表规则：

- 只显示直接 `CHILD` 节点。
- 不混入兄弟节点、推荐内容或搜索结果。
- 只读取当前发布版本并在服务端完成权限过滤。
- 权限不足的节点不出现，也不泄露数量。
- 人工排序优先，其次按节点类型和名称排序。
- 大列表使用分页或虚拟滚动。
- 叶子节点保持右侧区域并显示“暂无下级内容”。

所有内容均可归档，但只有明确允许导航的节点出现在右侧：

```text
navigation_visible
navigation_title
navigation_summary
navigation_thumbnail
navigation_order
```

图纸目录、档案、图纸页和 OCR 区域默认不进入公众导航；只有 `navigation_visible = true` 且权限允许时才展示。

## 8 固定业务数据模型

正式字段采用固定关系模型，不采用 EAV 或任意 JSON。单值信息使用固定表和固定列；历史事件、建造阶段、巡检和修缮等重复数据使用固定结构的明细表。

核心实体包括：

- `project`：项目。
- `place`：处。
- `natural_building`：自然幢。
- `content_node`：特色部位、构件、图纸和档案等内容节点。
- `node_relation`：结构父子关系和引用关系。
- `node_asset`：主图、缩略图、全景、模型和其他媒体。
- `node_revision`：不可变节点版本。
- `change_set`：一次编辑涉及的节点和关系变更。
- `building_release`：整栋建筑原子发布版本。
- `node_view_snapshot`：Web 已发布展示快照。
- `evidence_reference`：字段、事件或说明对应的图纸和档案证据。

字段新增必须通过数据库迁移、接口版本和快照 Schema 版本正式升级。暂时不能结构化的内容只能进入档案正文或备注，不能冒充正式字段。

## 9 身份信息

身份信息固定包含：

- 建筑唯一编号；
- 标准名称、曾用名和别名；
- 所属项目、处和自然幢；
- 地址和行政区划；
- 经纬度、地图范围和建筑轮廓；
- 保护身份、保护等级、公布批次和公布日期；
- 权属单位和管理单位；
- 当前主要用途；
- 铭牌名称、铭牌编号和铭牌文字；
- 数据状态、审核状态和权限等级。

名称、地址和保护身份变化时创建新节点版本，不覆盖历史发布版本。

## 10 建造信息

建造信息分为当前建筑概况和多条建造阶段。

当前概况固定包含：

- 始建年代、竣工日期和日期精度；
- 设计者、设计单位和施工单位；
- 建筑风格；
- 结构体系；
- 地上和地下层数；
- 建筑高度；
- 占地面积和建筑面积；
- 主要材料；
- 屋面形式；
- 立面特征；
- 平面布局概述；
- 保存完整度。

建造阶段类型固定支持原始建造、扩建、加建、改建、重建和用途改变引起的空间调整。每个阶段记录起止时间、参与单位、涉及部位、变更说明和证据。

形成建筑形态的历史改建归入建造阶段；日常维修、巡检和当代修缮归入运维信息。

## 11 历史人文信息

历史人文采用“建筑级摘要＋结构化事件＋关联人物＋价值评估＋档案证据”。

建筑级信息固定包含：

- 历史沿革摘要；
- 原始用途；
- 历史名称；
- 重要历史阶段；
- 代表人物；
- 重要机构；
- 社会文化影响；
- 现状说明。

历史事件固定包含事件类型、标题、起止日期、日期精度、事件说明、人物、机构、关联部位、地点、来源档案、审核状态和权限等级。日期精度支持确切日期、月份、年份、年代和约数。

价值评估固定包含：

- 历史价值；
- 艺术价值；
- 科学技术价值；
- 社会文化价值；
- 环境与城市景观价值；
- 代表性与稀缺性；
- 完整性与真实性；
- 综合评估结论；
- 评估单位、人员和日期。

历次价值评估完整保留，页面显示当前发布版本中的有效评估。RAG 可以提出候选事件、人物、日期和结论，但只有人工审核后才能进入正式字段和发布版本。

## 12 运维信息

运维分为当前状态和过程记录。

当前状态固定包含：

- 当前用途和使用单位；
- 管理单位；
- 开放状态和使用状态；
- 建筑完损等级；
- 安全风险等级；
- 消防状态；
- 最近巡检和修缮日期；
- 监测设备状态；
- 当前主要问题摘要；
- 管理责任人和联系方式；
- 数据更新时间。

过程记录固定支持巡检、病害或问题、修缮项目、日常维护、监测异常、安全或消防事件和应急处置。每条记录包含类型、时间、状态、责任单位、责任人、问题描述、处置措施、结果、关联节点、现场图片、相关档案、审核状态和权限等级。

运维问题优先关联到特色部位或具体构件；无法定位时才允许关联自然幢根节点。问题可以进一步引用图纸或 OCR 区域、现场照片标注、历史档案和后续修缮记录，形成“构件 → 问题 → 巡检证据 → 处置 → 复核结果”。

## 13 权限

访问范围固定为：

```text
PUBLIC
PROJECT_SCOPE
INDUSTRY_SCOPE
INTERNAL
RESTRICTED
```

权限作用于：

- 节点是否可发现和进入；
- 字段是否可读取；
- 原图、高清图、模型和裁剪图等媒体是否可读取；
- 关系和子节点是否可出现在列表中。

角色与范围：

- 公众只读已发布的 `PUBLIC` 内容。
- 项目管理人员通过项目成员关系获得项目、处和自然幢范围。
- 行业管理人员通过行政区划、管理类型和指定建筑例外获得范围。
- 编辑人员维护草稿但不能发布。
- 审核人员审核字段、媒体、图纸 OCR 和历史档案。
- 发布人员执行整栋建筑原子发布。

RAG 必须在候选召回前应用相同权限，不能先读取无权数据再隐藏答案。对象存储资源由服务端授权或短时签名读取。

## 14 Web API

主要页面接口：

```http
GET /api/web/home
GET /api/web/nodes/{nodeId}/view
GET /api/web/nodes/{nodeId}/children
```

`/view` 可以在首屏同时返回轻量 `children`，独立 `/children` 用于分页和继续加载。

固定页面查询使用 SQL 和展示快照：

- 首页地图和 slider；
- 当前节点完整信息；
- 路径和直接子节点；
- 建筑基本信息；
- 历史事件时间轴；
- 当前运维状态；
- 巡检和修缮记录；
- 媒体、全景和模型。

## 15 受控知识查询目录

图纸和档案知识查询使用受控 `queryCode`，前端不指定 SQL、搜索引擎或模型：

| 查询编码 | 用途 |
| --- | --- |
| `DRAWING_BY_TYPE` | 按总平面、平面、立面、剖面等类型查图纸 |
| `DRAWING_BY_FLOOR` | 查询指定楼层图纸 |
| `DRAWING_BY_TAG` | 按门窗、房间号、轴线号等 OCR Tag 定位 |
| `DRAWING_REGION_DETAIL` | 返回区域 bbox、裁剪图、OCR 文本和子节点 |
| `COMPONENT_DRAWING_LOCATION` | 查询构件在图纸中的位置 |
| `ARCHIVE_BY_PERIOD` | 按时期查询历史档案 |
| `ARCHIVE_BY_PERSON` | 查询人物相关档案 |
| `HISTORY_EVENT_EVIDENCE` | 查询历史事件的档案证据 |
| `FIELD_SOURCE_TRACE` | 追踪正式字段的图纸或档案来源 |
| `BUILDING_KNOWLEDGE_ANSWER` | 在当前权限和发布版本内综合问答 |

统一请求示例：

```json
{
  "queryCode": "DRAWING_BY_TAG",
  "contextNodeId": "building-001",
  "parameters": {
    "tag": "F-07",
    "floor": "2F"
  }
}
```

返回结果区分正式数据、候选检索结果、证据来源、可信度和审核状态。目录与元数据先通过 SQL 精确过滤，OCR、关键词和向量检索只在允许的候选范围内执行。

## 16 上传与异步处理

文件处理流程：

```text
上传原文件
→ 病毒和格式检查
→ 提取页码与元数据
→ 生成缩略图
→ OCR 和区域识别
→ 生成区域裁剪图
→ 建立结构化 Tag
→ 建立关键词与向量索引
→ 人工审核
```

原文件永久保留。OCR 文本、bbox、裁剪图和模型推断属于可重建派生数据，但每次处理必须记录模型、模型版本、prompt、prompt 版本、源文件校验值和处理时间。

处理状态：

```text
UPLOADED → PROCESSING → READY
                    └→ PROCESSING_FAILED
```

只有 `READY` 的资源才能提交内容审核。

## 17 编辑 审核与发布

所有修改先进入变更集：

```text
创建变更集
→ 新增 编辑或移动节点
→ 上传与自动处理
→ 人工校对
→ 分项审核
→ 整栋建筑原子发布
```

内容审核状态：

```text
DRAFT → IN_REVIEW → APPROVED → PUBLISHED
                └→ CHANGES_REQUESTED
PUBLISHED → SUPERSEDED
```

- 编辑字段生成不可变节点版本。
- 移动节点生成新的关系版本。
- 删除采用版本内逻辑移除，不物理删除历史数据。
- 提交审核后版本锁定，退回必须填写原因。
- 允许节点、字段和 OCR 区域分项审核。
- 只要本次发布范围内的必需项未通过，整栋建筑不能发布。
- 发布成功后生成建筑发布版本、受影响节点展示快照、有效 RAG 索引指针和缓存失效事件。
- 已发布版本不能编辑，只能创建后续版本。

编辑使用基础版本执行乐观锁校验。如果节点已被其他人修改，系统必须要求重新编辑、对比合并或另存变更集，不能静默覆盖。

## 18 失败与降级

- Web 页面不依赖运行时模型，Agile Agent 故障不影响普通浏览。
- 新节点数据加载失败时保留当前聚焦状态并显示可重试提示。
- OCR 或索引失败只影响草稿处理，不影响当前发布版本。
- 发布校验或索引构建失败时不切换建筑发布指针。
- 关键媒体缺失时阻止发布。
- 知识查询超时时返回已有结构化数据和证据，不编造答案。
- 权限变化使缓存失效，禁止复用其他权限范围的响应。

## 19 测试重点

### 19.1 前端与接口

- 首页点击地图进入“处”，点击 slider 直接进入自然幢。
- 路径点击、浏览器前进后退和深链接正确恢复节点。
- 节点切换不产生整页跳转或空白闪烁。
- 右侧只出现直接且可导航的子节点。
- 中部信息区和右侧列表可以独立滚动。
- 叶子节点保持布局并显示空状态。

### 19.2 数据与版本

- 固定字段类型、必填规则和接口映射一致。
- 草稿修改不影响已发布快照。
- 并发查询只看到完整旧版本或完整新版本。
- 历次历史事件、价值评估、建造阶段和运维记录可追溯。
- 问题记录可以准确关联部位、构件和证据。

### 19.3 权限与检索

- 项目人员不能访问其他项目。
- 行业人员只访问授权行政区划、管理类型和例外建筑。
- 隐藏节点不泄露标题、数量、媒体或搜索命中。
- RAG 在召回前执行权限过滤。
- `queryCode` 不能被用于传入任意 SQL、任意索引条件或越权节点 ID。

## 20 关键设计决策

- 首页和聚焦状态位于同一页面，使用可恢复的节点路由状态。
- 聚焦状态固定为左侧路径、顶部地图、中部当前节点和右侧直接子节点。
- 各节点类型复用统一 `NodeView`，正式字段固定。
- SQL 和展示快照负责正式页面，RAG 不参与普通页面渲染。
- 所有节点均可归档，只有显式允许导航的节点进入右侧列表。
- 同一份发布快照按节点、字段、媒体和关系权限过滤。
- 项目权限基于项目成员关系，行业权限基于行政区划、管理类型和指定建筑例外。
- 历史人文采用结构化事件和可版本化价值评估。
- 运维问题优先关联到具体部位或构件。
- 异步处理可以自动运行，未经审核的结果不能发布。
- 审核可以分项进行，发布必须按整栋建筑原子完成。
- Agile Agent 是受控智能查询能力，不是 Web 服务或正式数据存储的替代品。
